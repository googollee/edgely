# ADR-0011：传感器数据分两层处理——设备适配层重整原始数据，使用方消费整理后的流

## 背景（Context）

### 问题：重整和使用混在一处

ADR-0010 决定校准时间轴按采样序号重建。最初的实现把重建放在取窗口的地方：先从一个固定上限的滚动缓冲里按窗口起点切片，再对这一个窗口做"序号 vs 到达时间"的最小二乘，最后交给校准算法。这带来三个问题：

- **同一个样本在不同窗口里得到不同的 `t`**：时间轴在窗口内拟合，窗口一变，周期估计和时间零点都跟着变。重整结果依赖切片方式，而不是数据本身的性质。
- **重整规则只服务校准**：录制阶段拿不到同样的重整结果，以后任何新的"根据经验或协议说明重整数据"的规则（零偏修正、丢帧处理等）都得在两处各写一遍。
- **缓冲区大小由重整层决定，需求却来自使用方**：滚动缓冲的上限是拍出来的数字，与任何使用方的真实需求无关。

此外，以后可能接入 WIT 以外的设备，设备协议的细节（帧格式、寄存器、单位）不应该泄露到校准流程里。

### 重整需要多少历史

重整所需的回看长度和使用方需要保留的历史是两件事：

- **重整所需**：按采样序号重建 `dt` 只需要周期，而周期是硬件常量（晶振漂移 ppm 量级）。到达时间单边抖动 0–30 ms，对序号做最小二乘的周期误差粗估约为 30/N^1.5 ms（N 为帧数；抖动成对且落在 30 ms 网格上，实际再差到约 1.5 倍）：50 帧（1 秒）约 0.4%，100 帧约 0.15%，300 帧约 0.03%。累积越多越准，1 秒以上对 `dt` 已经足够。周期可以随数据流递推估计，不需要保存窗口。
- **使用方所需**：由使用方自己决定。校准会话有上限（四步、每步至多 10 秒，50Hz 下每个传感器约 2000 条，内存可以忽略）；录制边收边落盘，根本不需要窗口。

## 决策（Decision）

我们决定：**把传感器数据处理拆成两层——设备适配层按经验和协议说明重整原始数据，输出一条稳定的采样流，不做切片、不保存历史；使用方（校准流程、录制）只消费这条流。**

### 第一层：设备适配层（`DeviceAdapter`）

- **输入**：设备原始数据（WIT：从 BLE 解析出的实时帧，含加速度、角速度，以及所在数据包的到达时间）。
- **输出**：一条整理后的采样流 `DeviceSample`——帧序号、重建时间 `t`、统一单位的加速度（g）和角速度（deg/s）、所在数据包的到达时间（只用于把样本对应到用户点击的时刻、以及落盘分析，算法不读）。设备协议的细节到这里为止。
- **只重整，不切片**：输出是整条流，窗口切片由使用方按需做。
- **不保存历史**：样本整理出来就交给订阅者，没人订阅时直接丢弃。
- **落盘存原始数据，不存整理后的结果**：规则变了，旧数据可以重新整理。因此使用方落盘时要同时保留到达时间与帧序号。
- **重整逻辑是纯计算，不依赖 CoreBluetooth**：可以用落盘数据直接回放做单元测试。
- **时间轴按流式重建**：
  - 样本到达时给出 `t[i] = t[i−1] + 当前周期估计`，发出之后不再修改。
  - 周期估计是"序号 vs 到达时间"的带遗忘递推最小二乘，只保留几个累计量，不保存窗口缓冲。
  - 估计值向名义周期收缩并限幅：数据少时主要由名义值决定，数据多了由数据决定，不会因为开头几帧的抖动把周期带偏。名义周期由设备的回传速率给出。
  - 参数：遗忘时间常数 20 秒；收缩强度相当于 100 帧的窗口；估计值限制在名义值 ±2% 以内。
  - 时间零点（多传感器对齐时才需要）可以取 `到达时间 − i·周期` 的下包络，因为到达时间只会晚于真实时刻；现阶段不实现。
- **接口**：
  - `id`：稳定的设备身份；
  - `onSample`：每个样本回调一次，单订阅者；
  - `resetStream()`：帧序号从 0 重新计数，时间轴估计回到冷启动，用在回传速率刚改过、或一次新的使用开始之前。
- **状态仅限**：周期估计、递推累计量、帧计数。以后需要回看更多历史的重整规则（例如丢帧检测）在本层追加，不影响使用方。
- **设备专有能力留在具体类型上**：目前唯一的实现是 WIT（`WitDeviceAdapter`）。WIT 专有的数据（欧拉角、磁场、电量）和录制阶段带到达时间的回调留在这个具体类型上，不进协议。

### 第二层：使用方

- **校准流程**订阅第一层的流，自己决定怎么缓存：一个校准会话从开始到结束累积全部整理后的样本，结束即丢弃；窗口按两次点击的时刻从会话累积里切出（见 ADR-0012）。
- **录制**边收边落盘，不需要窗口。录制阶段目前没有使用这条流，仍用 WIT 适配器带到达时间的回调；是否迁移、录制记录的 `t` 是否改用重建时间，是单独的决定。

## 备选方案（Alternatives Considered）

### 方案 A：单层，每个窗口各自重整（不采纳）

- 优点：结构最简单。
- 缺点：同一样本在不同窗口里 `t` 不同；重整规则只在校准里生效；设备细节泄露到校准流程。
- 未采纳原因：新的重整规则无处可放，且与接入新设备的需求冲突。

### 方案 B：第一层同时负责窗口切片（不采纳）

- 优点：使用方拿到的就是现成窗口，调用面最小。
- 缺点：窗口边界是点击事件，属于流程语义，不是数据性质；第一层绑上窗口，就又回到"同一样本不同窗口不同 `t`"。
- 未采纳原因：违背第一层只重整的原则。

### 方案 C：用设备片上时钟给第一层校时（不采纳）

- 优点：片上时钟与采样节拍同源，可以提供比到达时间更好的锚点，并为丢帧提供旁证。
- 缺点：只能逐次轮询快照，要持续占用同一条 BLE 链路；需要额外的锚点对齐逻辑。
- 未采纳原因：按序号重建已经够用（见 ADR-0010 方案 B）。

## 后果（Consequences）

- 正面：
  - 重整规则只写一处，使用方共用同一份整理后的数据。
  - 同一样本的 `t` 与窗口无关，重整可以用真实数据离线回放，规则变化可回归。
  - 接入新设备只需实现 `DeviceAdapter`，校准流程不用改。
  - 历史留多久由使用方决定，没有固定上限。
- 负面 / 需要承担的代价：
  - 时间轴估计的参数（分位点、上跳惩罚、候选窗口）以代码为准（`LossAwareSampleClock`，ADR-0014），调整只改代码，不需要新建 ADR。
  - 丢帧仍然检测不了（协议没有序号）。
  - 录制与校准暂时走两条不同的出口，直到录制迁到采样流上。
- 对后续工作的影响：
  - 模块划分、数据流、缓冲区生命周期按本 ADR 描述，见 docs/design/system-design.md。
