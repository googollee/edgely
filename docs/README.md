# 文档说明

本文档体系面向个人和小团队，文档分四类，每类只做一件事，信息只有一个权威来源。本文件是文档规则的权威来源。

```
docs/
├── README.md                   # 本文件
├── review.md                   # 各类文档的目标、范围、越界示例
├── prd.template.md             # PRD 模板
├── design.template.md          # 设计模板
├── reference.template.md       # 参考文档模板
├── prd.md                      # PRD
├── design.md                   # 设计
├── design-<模块>.md            # 模块设计（可选）
├── reference/
│   └── <english-slug>.md       # 参考文档
└── adr/
    ├── 0000-template.md        # ADR 模板
    └── NNNN-<english-slug>.md  # ADR
```

## 四类文档

- **PRD**：做什么、为谁做、什么场景、不做什么。
- **设计**：当前系统的中高层设计，随项目演进更新。
- **ADR**：一个决策一份文件，记录当前决策、依据、备选方案和影响。
- **参考**：本项目对外接口与契约（如 AttSensorKit 的设备适配接口）的权威描述，只写契约，不涉及具体设备的协议或实现。

## 引用规则

- PRD 不引用其他文档。
- ADR 可引用 PRD 需求，不引用设计和其他 ADR。唯一例外：废弃的 ADR 在 `status` 中注明取代它的 ADR，写编号即可，不用链接。
- 设计可引用 PRD 需求和生效的 ADR。`design.md` 可引用模块设计，模块设计不引用 `design.md`，模块设计之间也不互相引用。
- 参考文档不引用其他文档；ADR 和设计可以引用它。
- 引用时用链接，不复述被引用文档的内容。

## 修改规则

- PRD、设计、参考文档：直接修改，历史由 git 记录，文档中不写演进过程。
- ADR：提议状态可自由修改。生效后决策不变，只允许修改 `status`、错别字、与事实不符的笔误、失效的需求链接（依据仍成立时改为新编号），以及 review 发现的越界内容。决策变化时新建 ADR，旧 ADR 改为废弃。
- 废弃的 ADR 保留文件，只修改 `status`；其中失效的需求链接保持不动。

## 需求编号

- 编号为 `F-001` 形式，统一不分类，编号不复用。
- 需求标题只写编号，名称写在标题下一行。标题即链接锚点，如 `prd.md#f-001`。
- 需求含义实质变化时，删除旧编号，启用新编号，并检查引用旧编号的 ADR 和设计。ADR 的依据不再成立时，新建 ADR 取代它。

## ADR 状态

`status` 以下列三个词之一开头：

- 提议：尚在讨论，可自由修改
- 生效：已定稿
- 废弃：不再生效，原因写在括号内，如 `废弃（被 0012 取代）`

## ADR 编号

- 四位编号，取现有最大编号加 1，`0000` 为模板。
- 文件名为四位编号加英文 slug，如 `0001-storage-engine.md`。
- 并行分支合并时编号冲突，后合并的一方改号。

## 变更顺序

代码必须符合设计。涉及设计的变化：

- ADR 处于提议状态时，可以在分支上修改代码进行验证，此时分支上的代码可以与设计不一致。
- 合入主线时，相关 ADR 必须已生效，设计已同步更新，代码与设计一致。

## 如何新建

- PRD：复制 `prd.template.md` 为 `prd.md`
- 设计：复制 `design.template.md` 为 `design.md`
- 模块设计：设计文档过大时，复制 `design.template.md` 为 `design-<模块>.md`；`design.md` 只保留总体与模块间协作，并链接各模块设计
- 参考文档：复制 `reference.template.md` 为 `reference/<english-slug>.md`
- ADR：复制 `adr/0000-template.md` 为 `adr/NNNN-<english-slug>.md`

## Review

每次实质修改后，对照 `review.md` 中对应类型的目标和范围，检查是否有越界内容。每份文档 frontmatter 的 `review` 字段指向对应章节。
