# 0013 磁场数据按 0.5 秒间隔轮询，落盘为独立记录

## 决策

1. 录制期间按固定 0.5 秒（2Hz）轮询磁场寄存器，不跟随加速度 / 角速度的回传速率。这个频率落在官方 Demo 的节奏区间内。
2. 磁场读数落盘为独立的一行记录（`type: "magnetic"`），不合并进加速度 / 角速度的 `sample` 记录。记录的时间戳就是这次读数到达的时刻。

## 依据

- 需求：[F-003](../prd.md#f-003)。
- MVP 阶段为留档尽量多采集数据，磁场读数也在录制范围内，但不参与任何计算。
- WT9011DCL-BT50 的磁场不随实时数据帧推送，只能通过读寄存器 `0x3A` 按需获取，每次读取是同一条 BLE 链路上的一次命令 / 响应。官方资料里没有磁力计内部采样率的指标，官方三个平台的参考 Demo 轮询节奏在约 1–3Hz 之间，都在读取命令旁注明"不需要读那么快的数据"。
- 加速度 / 角速度的回传速率固定为 50Hz，远高于磁场的读取频率。

## 备选方案

### 跟随回传速率轮询（50Hz）（未采纳）

磁场与加速度 / 角速度一一对应。但没有证据表明磁力计内部更新得这么快，多读到的只是重复值；命令 / 响应流量与回传速率同量级，会挤占同一条 BLE 链路，固件对高频读命令的处理也未知。增加风险，没有对应收益。

### 把最近一次磁场读数合并进每条 `sample` 记录（未采纳）

每行字段齐全，读取方便。但轮询频率远低于回传速率，绝大多数 `sample` 里的磁场字段只是上一次读数的复读，容易被后续分析误当成"这一刻采到了新数据"，混淆磁场数据真实的采集时刻。

## 影响

- BLE 链路上的额外流量很小，不影响实时帧。
- 磁场记录的时间戳就是真实采集时刻，分析时不会和加速度 / 角速度混淆，但需要按时间把磁场记录与 `sample` 记录对齐。
- 2Hz 是否足够反映磁场的变化没有依据可查；将来若要用磁场参与计算（如偏航），需要重新评估轮询频率。
- 若官方资料或实测给出磁力计内部采样率，需要据此重新评估。
