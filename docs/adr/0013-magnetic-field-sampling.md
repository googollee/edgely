# ADR-0013：磁场数据按 0.5 秒间隔轮询，落盘为独立记录

| 字段 | 内容 |
| --- | --- |
| 状态 | 已采纳 |
| 日期 | 2026-10-04 |
| 决策者 | Googol Lee |
| 关联 PRD | docs/prd/mvp.md（F3、数据存储设计） |

## 背景（Context）

MVP 阶段为留档尽量多采集数据，磁场读数也在录制范围内，但不参与任何计算。

WT9011DCL-BT50 的磁场不随实时数据帧推送，只能通过读寄存器 `0x3A` 按需获取，每次读取是同一条 BLE 链路上的一次命令 / 响应。官方资料里没有磁力计内部采样率的指标。官方三个平台的参考 Demo 轮询节奏在约 1–3Hz 之间，都在磁场读取命令旁注明"不需要读那么快的数据"（见硬件协议参考文档「磁场寄存器的读取节奏」）。

accel / gyro 的回传速率固定为 50Hz（录制不可选），远高于磁场的读取频率。

## 决策（Decision）

我们决定：

1. **录制期间按固定 0.5 秒（2Hz）轮询磁场寄存器**，不跟随 accel / gyro 的回传速率。这个频率落在官方 Demo 的节奏区间内。
2. **磁场读数落盘为独立的一行记录**（`type: "magnetic"`），不合并进 accel / gyro 的 `sample` 记录。记录的时间戳就是这次读数到达的时刻。

## 备选方案（Alternatives Considered）

### 方案 A：跟随回传速率轮询（50Hz）（不采纳）

- 优点：磁场与 accel / gyro 一一对应。
- 缺点：没有证据表明磁力计内部更新得这么快，多读到的只是重复值；命令 / 响应流量与回传速率同量级，挤占同一条 BLE 链路，固件对高频读命令的处理也未知。
- 未采纳原因：增加风险，没有对应的收益。

### 方案 B：把最近一次磁场读数合并进每条 `sample` 记录（不采纳）

- 优点：每行数据字段齐全，读取方便。
- 缺点：轮询频率远低于回传速率，绝大多数 `sample` 里的磁场字段只是上一次读数的复读，容易被后续分析误当成"这一刻采到了新数据"。
- 未采纳原因：会混淆磁场数据真实的采集时刻。

## 后果（Consequences）

- 正面：
  - BLE 链路上的额外流量很小，不影响实时帧。
  - 磁场记录的时间戳就是真实的采集时刻，分析时不会和 accel / gyro 混淆。
- 负面 / 需要承担的代价：
  - 分析时需要按时间把磁场记录与 `sample` 记录对齐。
  - 2Hz 是否足够反映磁场的变化，没有依据可查；将来若要用磁场参与计算（例如偏航），需要重新评估轮询频率。
- 对后续工作的影响：
  - 若官方资料或实测给出磁力计内部采样率，据此重新评估轮询频率，届时新建 ADR。
