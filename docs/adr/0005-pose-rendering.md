# 0005 姿态渲染使用鞋形简化几何体 + 校准对齐 + 加速度计倾斜锚定

## 决策

1. **几何体**：用一个简化的、不对称的鞋形组合形状（如长方体主体 + 一端加锥体或楔形表示脚尖，鞋底面用不同颜色区分）表示脚的姿态，在固定的模型局部坐标系里预先定义"脚尖方向"和"鞋底方向"。仍是简化几何体，不是精细雪靴/雪板模型。
2. **校准对齐（常量，一个 session 内只计算一次）**：用校准阶段算出的参考系（`SensorOrientationFrame` 的 `front` / `down` / `left`，在传感器原始坐标系下表达）计算"模型局部坐标系 → 传感器坐标系"的对齐旋转，使鞋形模型的朝向与真实鞋对齐。
3. **实时倾斜（每个回放时间点计算）**：不使用传感器的 Angle 字段，改用原始加速度计读数，计算"相对校准时刻的重力方向，当前时刻转了多少"（最短路径旋转），叠加在对齐旋转之上，驱动模型的实时姿态。

## 依据

- 需求：[F-002](../prd.md#f-002)、[F-005](../prd.md#f-005)。
- 对称方块没有任何视觉线索表明哪面是脚尖、哪面是鞋底，观察者无法把渲染结果和真实的鞋对应起来。
- 直接用 Angle 字段驱动无法保证"下"方向在回放中始终朝下：传感器欧拉角的旋转顺序和正负号约定是否与 SceneKit 的 `eulerAngles` 一致尚未验证。加速度计的换算公式已核实、没有歧义，更适合现阶段使用。
- 校准算出的参考系原本只落盘、回放没有使用，用来做对齐能让它发挥作用。

## 备选方案

### 继续用对称方块/箭头（未采纳）

实现成本最低，是此前的状态。但无法解决"看不出模型朝向与真实鞋对应关系"的问题。

### 用 Angle 字段（传感器内部融合的姿态角）驱动实时姿态（未采纳）

理论上包含完整三轴姿态（含偏航），信息量更完整。但依赖尚未验证的欧拉角约定，用错会导致姿态方向错误且不易察觉。在约定验证清楚之前，风险高于收益。

### 用陀螺仪角速度积分重建完整姿态（未采纳）

能得到含偏航的完整姿态，不依赖欧拉角约定。但需要一套传感器融合算法（陀螺仪积分 + 加速度计校正以避免长时间漂移），复杂度明显高，属于分析算法范畴，MVP 阶段不做。

## 影响

- 观察者能直观看出模型的脚尖/鞋底朝向，"下"方向始终锚定在真实重力方向。
- 使用的是已核实、无歧义的加速度计原始数据，不引入新的不确定性。
- 加速度计只能测倾斜（俯仰和横滚两个自由度），测不出绕重力轴的偏航，所以渲染不含偏航，滑雪时脚绕纵轴的转向不会体现在模型转动上。这是方案的已知局限。
- 如果后续要还原含偏航的完整姿态，需要先验证欧拉角约定，再评估改用 Angle 字段或做完整传感器融合。
