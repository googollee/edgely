# ADR-0008：校准流程为"前迈定坐标 + 后迈做校验"的五步动作

## 背景（Context）

F2 校准靠用户完成一组引导动作，从动作的传感器读数里反推每只脚的参考系和左右身份。需要决定这组动作具体是什么，以及每个动作的读数用来做什么。

约束来自三个方面：

- **算法**：每只脚至少要有一次能算出方向的动作（ADR-0007 的算法对动作方向没有要求，前迈、后迈、侧迈都能算，只是算出的方向不同）；身份判定需要两侧可比的动作（见 ADR-0006）。
- **雪靴场景**：雪靴限制踝关节内外翻，侧向动作比前后动作别扭得多；现场戴着手套、视线不便，动作和指令都应当尽量简单。
- **窗口纯净度**：判定窗口按时间截取，不区分"过渡动作"和"目标动作"。如果流程要求用户在两步之间"先把上一步迈出去的脚收回来"，这个收脚动作会落进下一步的判定窗口，污染本该接近 0 的读数。因此流程结构上应当避免产生需要收脚的过渡。

此外，算出的坐标目前没有任何核对手段——算完即采信。由于 ADR-0007 的算法依赖一串未经现场验证的阈值，缺少核对手段意味着一次不可靠的校准会静默地进入后续所有数据。

## 决策（Decision）

### 五个步骤

| # | 动作 | 用途 |
| --- | --- | --- |
| 1 | 双脚并拢自然站立、雪靴放平，站稳 | 每个传感器各记录一次重力方向，作为该传感器的"下"基准轴 |
| 2 | 左脚向前迈一步，站稳 | 算左脚参考系；参与身份判定（双传感器在本步结束时即可判定） |
| 3 | 左脚不动，右脚向前迈一步与左脚并拢，站稳 | 算右脚参考系；单传感器在本步结束时才能判定身份 |
| 4 | 左脚向后迈一步，站稳 | 校验左脚方向 |
| 5 | 右脚向后迈一步，站稳 | 校验右脚方向 |

步骤 2、3 构成一个"一脚不动、另一脚迈步"的结构：左脚迈出去之后留在原地，右脚直接迈过去并拢。这个结构不需要任何收脚过渡，因而不会产生上述的窗口污染。步骤 4、5 同理。走完五步双脚回到起点，流程是闭环的。

每一步都要求**动作前后各停稳一次**——ADR-0007 的算法把“动作起止速度为零”当作消除积分误差的边界条件，两端没停稳这个前提就不成立。指令还要求**沿脚尖方向直着迈**，因为算出的"前"是运动方向而非脚尖朝向（见 ADR-0007），直着迈能把两者的偏差压到最小。

### 前迈定坐标，后迈做校验

- **坐标只取前迈窗口**：每只脚的参考系只用该脚前迈那一步的数据算（ADR-0007 的算法），直接作为最终输出，不与后迈结果做平均或融合。
- **身份判定只用前迈窗口**：机制与阈值见 ADR-0006。双传感器在步骤 2 内比较两个传感器，身份当场确定；单传感器要比较步骤 2、3 两个窗口，身份到步骤 3 结束才确定。
- **后迈只做校验**：步骤 4、5 的窗口同样跑一遍 ADR-0007 的算法，得到的方向应当与对应前迈方向相差 180°，夹角偏差超过 `verificationToleranceDegrees`（当前占位值 30°）即判定校准失败。这个方向不进入坐标计算。容差比 ADR-0007 的姿态漂移自检更宽松，因为这是两次独立完成的人体动作，一致性天然弱于同一次动作内部。

### 单传感器与双传感器走完全相同的流程

**无论接 1 个还是 2 个传感器，五个步骤都完整走完**，流程不因传感器数量、也不因身份判定结果而分支。

单传感器场景下，有一半的后迈校验落在没有传感器的那只脚上，什么也验证不了，但那一步仍然要求用户做完。这样做有两个理由：指令序列恒定，用户不需要按场景记两套动作；流程本身也不会泄露身份判定结果——如果只让用户做"系统认为装了传感器的那只脚"的校验，用户就能从指令反推出判定结果，而判错时他并没有办法判断哪个才是对的。

### "该动却没动"在校验步骤里是失败

到了后迈步骤，身份已经确定（双传感器在步骤 2、单传感器在步骤 3），哪个传感器应该动是明确的。被判定为这只脚的传感器如果在对应的后迈窗口里峰值速度达不到绝对下限（见 ADR-0006），判定为校准失败。

这条规则同时兜住了身份判错的情况：传感器装在左脚、而用户在步骤 2 误用右脚迈步时，身份会被判成"右"，走到步骤 5（右脚后迈）时系统期待这个传感器动、而它装在左脚上不会动，于是失败重来。

这条规则与前迈步骤**相反**：前迈时身份尚未确定，"这一步没动"可能只是因为传感器装在另一只脚上，是预期中的正常信号；后迈时身份已定，"没动"就一定是错的。

### 失败处理

**任何一项判定或校验没通过，整个校准流程从第一步重来，不做任何形式的局部重试。** 这是整个校准唯一的失败处理方式。

理由是语义清晰、实现和心智负担都最低：用户不需要理解"这次是重做一步还是重来一遍"，状态机也不需要维护"从中间某一步恢复"的能力。代价是任何一步失败都要重走五步，而当前所有判定阈值都是未经现场验证的占位值——一旦某个阈值偏严，用户会反复走完整个流程却无法推进。这把阈值标定的重要性推到很高的位置，也是 ADR-0009 把校准过程数据落盘的直接原因。

提示分成四类：**能对应到一个明确动作调整的给专门提示，其余统一兜底**。

| 失败 | 提示 |
| --- | --- |
| 从上一次确认起满 4 秒仍未点击（超时） | 动作太慢，请重新开始 |
| 应该动的那一侧峰值速度达不到下限 | 动作幅度太小，请重新开始 |
| 姿态积分漂移超限 / 方向一致性不足 / 后迈校验方向对不上 | 校准失败，请重新开始 |

前两类各自对应一个用户能照着改的行为，而且判据本身没有歧义空间（第一类只看两次点击的间隔，第二类是一个明确的下限）。最后一类即使告诉用户是哪一项，他也没有办法据此调整动作，所以保持粗粒度。需要细分信息的是事后调参，那部分由 ADR-0009 的落盘数据承担。

## 备选方案（Alternatives Considered）

### 方案 A：每只脚做"前迈 + 侧迈"两个动作

- 优点：两个动作方向正交，提供的信息比同轴的前后两次动作更丰富；侧迈数据可以作为身份判定的第二个窗口。
- 缺点：雪靴限制踝关节内外翻，侧向迈步别扭且幅度受限；侧迈是复合运动，噪声比前后迈步大，不适合直接反解坐标轴，因而只能用于辅助判定，换不来一次可用的方向估计；而且"左迈 → 收回 → 右迈"这类序列需要收脚过渡，会引入窗口污染。
- 未采纳原因：动作更难做，却换不来一次可用于校验的方向估计。

### 方案 B：前后各迈一次，两次结果融合成最终坐标（如 `normalize(f_forward − f_backward)`）

- 优点：如果前后两次结果都可信，融合能抵消两次动作共有的系统误差（重力补偿残差、零偏），精度理论上高于单用前迈。
- 缺点：需要额外决定融合权重、以及两次结果差异较大时如何处理（继续融合还是判失败），比"判断是否通过"的门槛检查复杂；用户对后迈这个动作的直觉预期是"再做一次给系统核对"，融合会让这个动作的语义变得含糊。
- 未采纳原因：当前需要的是一个提高可信度的核对手段，不是进一步压榨精度；融合的复杂度与这个诉求不成比例。

### 方案 C（采纳）：前迈定坐标，后迈只做通过/不通过的校验

- 优点：坐标来源单一、可预期；校验失败时语义明确（这次校准不可信）；复用 ADR-0007 现成的算法，新增逻辑只是一个夹角比较。
- 缺点：没有利用后迈数据提升坐标精度，比方案 B 保守。
- 未采纳原因：N/A（此为采纳方案）。

### 方案 D：单传感器跳过落在另一只脚上的校验步骤

- 优点：单传感器用户少做一个什么也验证不了的动作。
- 缺点：流程会因传感器数量和身份判定结果而分支，用户要记两套动作；更重要的是指令序列会泄露身份判定结果，而用户在判错时并没有办法识别哪个才是对的。
- 未采纳原因：省一个动作，换来流程分支和信息泄露，不划算。

## 后果（Consequences）

- 正面：
  - 动作全部是前后方向的迈步，符合雪靴场景的人体工学。
  - 流程结构不需要收脚过渡，从根上排除了窗口污染。
  - 身份判定在步骤 3 结束时完成，判定失败暴露得早，用户少做两个动作就知道要重来。
  - 坐标第一次有了核对手段，不再是算完即采信；"该动却没动"这条规则还顺带拦住了左右判错。
  - 失败处理只有一种，用户和实现都不需要区分失败类型。
- 负面 / 需要承担的代价：
  - **任何一步失败都要重走五步**。所有判定阈值都是占位值，阈值偏严会让用户反复走完整个流程而无法推进。
  - 单传感器场景下有一半的校验落空，用户仍要完成那个动作。
  - 校验步骤复用 ADR-0007 的完整算法，因此它本身也可能因为动作太慢、漂移过大而失败——用户可能遇到"前迈都过了、卡在后迈"的情况。
  - 校验容差（30°）是未经现场验证的占位值。
- 对后续工作的影响：
  - 校验容差需要现场数据回填，依据由 ADR-0009 落盘的校准数据提供。
  - 若现场测试显示后迈校验误判率过高（同一只脚前后两次动作的方向差异经常超出容差），需要新建 ADR 调整方案（放宽容差，或改用方案 B 的融合思路），并在此处标注取代关系。
  - 雪场坡度可能影响参考系的一致性：本流程跨越三个不同的落脚点（原点、前方一步、中间），而去重力统一使用站立基准。坡面上不同落脚点的脚掌倾角存在系统性差异，会让算出的参考系有小幅不一致（不触发失败，见 ADR-0007）。实际影响多大需要现场验证，必要时在指令里要求找一块平整的地方校准。
