# 文档目录

- `prd/`：产品需求文档（PRD）。每个阶段/大版本一份，文件名如 `mvp.md`、`v2-realtime-feedback.md`。
- `adr/`：决策记录（ADR）。命名沿用 Architecture Decision Record 的惯例，但记录范围不限于系统架构，只要是有备选方案、有取舍、未来可能被推翻的决策（架构选型、调优策略、算法选择、产品实现方式等）都可以写在这里。每条决策一个文件，编号递增，如 `0001-xxx.md`。
  - **提议中**：决策仍在形成，包括需要实验或数据验证的阶段，内容可以随时修改。
  - **已采纳**：即发布。发布后正文不再修改，只允许更新状态字段；后续变化另建新 ADR。
  - 决策被推翻时不删除旧文件，只在旧 ADR 的状态里注明 `已被取代（取代者：ADR-000Y）`；新 ADR 不反向引用被取代的 ADR。
- `reference/`：接口与协议参考文档。目前是 AttSensorKit 的接口协议（`att-sensor-kit-protocol.md`），只描述设备适配层的契约，不涉及任何具体设备的协议或实现。
- `design/`：系统设计文档。描述系统当前实际运作方式（模块划分、数据流、生命周期规则等），是随代码持续更新的"活文档"——不同于 ADR（记录某次决策发生时的因果，写完不为追随代码而重写）和 PRD（产品需求，不展开实现细节）。当决策的落地细节需要被后续开发/协作者查阅时，写在这里并引用对应 ADR。

模版文件统一命名为 `TEMPLATE.md`，复制后改名并填写内容。
