# Edgely MVP 设计

## 概述

Edgely 是一个 iOS App，用 1~2 个姿态传感器采集各类运动中的脚部姿态数据，并在事后回放。系统分三部分：

- **AttSensorKit**：本地 Swift Package，定义设备适配层的接口契约。app 只依赖它，不认识任何具体设备，见[接口参考](reference/att-sensor-kit-protocol.md)。
- **设备实现包（可选）**：具体设备的适配器，通过注册表接入。不存在时 app 仍可编译，只是没有设备可连。
- **Edgely（app 本体）**：连接、校准、录制、历史记录、回放。

传感器数据分两层处理：设备适配层把原始数据整理成统一的采样流，使用方（校准、录制）只消费这条流。App 的界面按 `连接 → 校准 → 准备录制 → 录制 → 回到连接` 的主流程串联，历史记录和回放是旁支入口。

## 组成与职责

### app 模块

| 模块 | 职责 | 对应需求 |

| Recording | 录制主流程（采样、断线检测、电量快照、磁场轮询）、GPS 记录、定位权限 | [F-003](prd.md#f-003)、[F-004](prd.md#f-004)、[F-006](prd.md#f-006) |
| App | 应用入口、阶段协调、设备注册点、电量监控 | [F-001](prd.md#f-001)、[F-013](prd.md#f-013) |
| Storage | session 数据的 JSON Lines 落盘 | [F-003](prd.md#f-003) |
| Models | 落盘用的数据结构 | — |
| UI | SwiftUI 视图：连接、校准、录制、历史、回放（含 3D 姿态渲染与位移展示） | [F-001](prd.md#f-001)、[F-005](prd.md#f-005)、[F-007](prd.md#f-007) |

- 校准引擎只依赖设备适配器协议，不依赖蓝牙，可以用 `MockAdapter` 脱离设备单测。
- 校准的纯计算部分（抬脚峰值速度、站立基准、活动段、前轴、身份比较）单独成模块，判定参数也在这里。

### 阶段状态机

`AppCoordinator` 持有阶段状态 `AppPhase`，统一协调切换：

```
.connect --(选传感器)--> .calibrate --> .ready --> .recording --(结束录制)--> .connect
   |                                                                            ^
   +--(历史记录入口)--> .history --(选中某个 session)--> .review --(返回)--> .history
                           |
                           +--(返回)--> .connect
```

- 录制结束后直接回到 `.connect`，清空当前校准和录制状态，已连接的传感器保持连接，不需要重新连接。
- `.review` 只能从 `.history` 进入，退出后也回到 `.history`。

### 设备注册与连接

- **注册**：app 创建设备适配器注册表。设备实现包存在时（编译条件 `EDGELY_DEVICES`）把自己的工厂注册进来，不存在时注册表为空。设备管理器用这个注册表创建。
- **扫描与认领**：设备管理器按注册表汇总的服务 UUID 扫描，命中某个工厂的设备才进入列表。注册表为空时不启动扫描，连接页提示"没有可用的设备支持"。DEBUG 构建里连接页有"添加模拟设备"按钮。
- **连接确认**：用户点"连接"后，管理器发现服务并交给归属工厂确认；通过才创建适配器并接手外设，不通过就断开，该行显示"不是支持的设备"。连接页只能选择已就绪的设备。
- **能力判断**：电量、磁场、欧拉角、回传速率设置都是可选能力，消费者用 `as?` 判断。例如电量监控只针对具备电量能力的设备，录制只对具备磁场能力的设备轮询磁场。
- **工程生成**：`make proj` 调用生成脚本，检测项目根目录下的 `EdgelyDevices/` 是否存在，存在则加入编译。工程文件不进版本管理。

### 连接与重连

设备管理器记录用户要求连接的外设。外设意外断开后，管理器通知适配器连接中断，并立刻重新发起连接；蓝牙关闭后重新开启时，对仍未就绪的外设重新连接，连接失败的隔 1 秒再试。校准、录制期间行为相同。

重连成功后适配器重新接手外设，采样流回到干净的起点（帧序号从 0 重新计数）。因此：

- 录制期间：断线时已写入 `gap_start`；重连后收到数据，写入 `gap_end`。
- 校准期间：窗口内出现帧序号重新计数，说明采样流中断过，这一步按失败处理。传感器在点击时仍处于断线状态的情形没有单独检测。

## 协作方式

### 数据流

```
设备数据（经设备管理器接手的外设，主线程回调）
  → 适配器：解析、统一单位、重建时间 → DeviceSample
  → onSample（设备适配层的标准输出），两个出口：
     - 校准阶段：校准引擎订阅，缓冲区累积整个会话、按点击切窗口
     - 录制阶段：录制会话订阅，逐条编码后写入存储；`t` 取自采样流，落盘后不再修改
       设备带欧拉角时，订阅带角度的回调，样本和同一帧的欧拉角一起落盘
```

两个阶段用同一路采样流，但生命周期不同：录制阶段的数据是 session 的正式内容，逐条落盘、不能丢；校准阶段的数据由校准流程自己累积（设备适配层不保存历史），其中交给判定的窗口另行复制一份落盘留档，累积的样本本身是临时工作区。

### 时间戳

`DeviceSample` 带两种时间：`arrival`（数据包到达手机的时刻，实测）和 `t`（适配器重建的时间，估计值）。语义见接口参考。两个阶段的用法：

- **校准**：交给算法的 `t` 是采样流的 `t`（`timeOrigin` 为空，窗口内再平移成相对窗口第一个样本）。原始到达时间保留为 `arrivalT`，随校准数据一起落盘。窗口只有几秒，丢帧修正在这里可以忽略。
- **录制**：录制开始时把设备的 `timeOrigin` 设为录制开始的时刻并重开采样流，停止时还原为空（设备之后还会用于校准）。`sample` 记录的 `t` 是采样流的重建时间，和 GPS、电量在同一基准。双传感器各自重建，起点都锚定在手机时钟上，对齐精度受到达时间的粒度限制。
- 字段含义见[数据格式参考](reference/session-data-format.md)。

### 校准阶段

步骤、判定、算法与失败处理见 [0012](adr/0012-calibration-flow.md)，本节只描述代码怎么运行。

- **进入校准**：对每个已连接的传感器设置回传速率为 50Hz（具备 `OutputRateConfigurable` 的调用 `setOutputRate`，同时重开采样流；不具备的只重开采样流）。传感器在两趟录制之间保持连接，所以每次校准都要重新设置一次，保证从一条新流开始。随后创建校准引擎和校准记录器，引擎订阅各传感器的采样流。
- **单步超时**：引擎在每个窗口起点（创建、每次点击、超时重置）启动一次性计时器，到点即判"动作太慢"并整体重来，重来的这一刻成为新窗口的起点；校准完成或关闭时取消。
- **每次点击确认**：先再检查一次距上一次点击是否超过单步时限（计时器之外的兜底）；再按 [上一次点击, 这一次点击] 的到达时间区间，从缓冲区切出每个传感器的窗口，`t` 平移成相对窗口第一个样本；窗口内帧序号不连续则这一步直接判失败；否则交给计算模块对应的函数，并通过记录器落盘原始窗口和判定结果。失败时丢弃全部中间状态、记录失败的尝试、回到第一步。
- **界面**：显示当前指令、单步倒计时、失败提示与身份判定提示。倒计时由视图本地计时器驱动。
- **校准结束**：阶段从 `.calibrate` 切到 `.ready`。引擎取消订阅、丢弃累积的样本、收尾落盘；成功那次的校准 id 随后写进 session 的 `meta.json`。

### 录制阶段

`AppCoordinator` 开始录制时创建录制会话：

- **创建时**：把采样流（设备带欧拉角的用带角度的回调）和磁场回调接到各传感器，设置回传速率（固定 50Hz，设备具备 `OutputRateConfigurable` 时），写入初始 `meta.json`（`endedAt` 为空）。
- **开始**：把适配器的 `timeOrigin` 设为录制开始的时刻并重开采样流（创建到开始之间收到的帧不属于这次录制），开始定位，并启动计时器：界面计时 0.2 秒、断线检查 0.5 秒、磁场轮询 0.5 秒、电量快照 1 分钟；同时读一次各传感器的电量，约 1 秒后记录开始时刻的电量快照，包含已连接传感器（具备电量能力的）和手机的电量。
- **断线检测**：每 0.5 秒检查各传感器的 `lastRealtimeAt`，超过 2 秒就写一条 `gap_start`（每段缺口只写一次）；之后收到下一帧实时数据时写 `gap_end`。只看实时数据，电量、磁场等响应不刷新这个时间，否则实时数据流停了而其他读取仍有回应时，缺口会被遮住。
- **结束**：停掉计时器和定位，把适配器的 `timeOrigin` 还原为空，再读一次电量；约 1 秒后（等设备回应）记录结束时刻的电量快照、写入带 `endedAt` 的 `meta.json`、关闭存储（含最后一次 fsync）。收尾闭包强引用会话，调用方在结束之后马上释放会话也不影响收尾。
- **后台运行**：靠 Info.plist 的 `UIBackgroundModes`（`bluetooth-central`、`location`）和定位的 `allowsBackgroundLocationUpdates`，App 切到后台后仍能收蓝牙数据、记录 GPS。

### 电量显示

连接页把电量放在设备行最左侧；准备录制、录制中两个页面顶部显示电量；校准、回放和历史页不显示。

- **布局**：顶部一行分成左右两半，左脚传感器在左半边、右脚传感器在右半边，内容是"左脚 85%"；只有一个传感器时另一半留空。没判定出左右脚的传感器放到还空着的那一半。只显示百分比，不画电量条。
- **挂载**：根视图在顶部挂电量显示，只在 `.ready`、`.recording` 阶段出现；没有被监控的传感器时不占空间。连接页的百分比由设备行直接读适配器的电量，已连接才显示。
- **数据来源**：`AppCoordinator` 持有电量监控，随阶段切换监控对象：连接页监控所有已发现的传感器，校准、准备录制、录制中监控用户选的那几个，历史和回放页停止监控。传感器就绪（含重连）时立刻读一次电量，之后每 60 秒轮询。读数带左右脚信息（来自校准结果）。录制会话每分钟的电量快照独立，两者互不影响。
- **颜色**：目前接入的设备给出的电量是分档的（100/90/75/60/50/40/30/20/15/10/5/0），所以"低电量"按 ≤ 10%，只有百分比变红，标签不变色。没有滞回。还没读到电量时显示"--%"，不算低电量。
- **断线**：不显示百分比，也不保留旧值。连接页该设备行不显示电量；准备录制、录制中槽位保留，显示"左脚 已断线"。重连后收到新读数前显示"--%"。

### 姿态渲染

回放页用 SceneKit 渲染一个简化的、不对称的鞋形组合几何体（不是精细的鞋模型）。时间轴可拖动，也可播放/暂停：播放按真实时间推进，拖动期间暂停推进，到终点自动停止。

- **渲染世界坐标系**：几何体和相机机位预先约定"脚尖=+Z、鞋底=-Y"，相机从 -Z 一侧朝 +Z 看，使静止姿态下脚尖朝屏幕里、脚跟朝屏幕外、鞋底朝下。
- **传感器坐标系 → 渲染世界坐标系（常量，一个 session 内只计算一次）**：用该 session 对应传感器的校准参考系（`front`/`down`/`left`，随 session 存入 `meta.json`）算出换算旋转。传感器和鞋是刚性固定的，这个关系在整个 session 内不变；传感器原始读数不能直接当渲染世界坐标用，两者是不同的坐标系。
- **实时倾斜（拖动时间轴时每个时间点计算）**：用该时刻的原始加速度计读数，先换算到渲染世界坐标系，再算出相对世界"下"方向的最短路径旋转，驱动模型。不使用欧拉角。
- **数据缺失**：回放页读取传感器文件时把 `gap_start`/`gap_end` 配成缺口区间。区间起点取缺口前最后一个采样点的时刻（`gap_start` 是连续 2 秒没数据才判定的时刻，真正缺数据的时间更早开始），终点是 `gap_end`；录制在断线期间结束时，最后一段缺口补到录制结束。回放页在时间轴下方画出缺口条，拖动到缺口内时显示"此时间段数据缺失"并隐藏该侧模型，不用缺口前的旧读数填充；摘要里列出每段缺口的起止时间。
- **局限**：姿态渲染只用加速度计，只能还原倾斜（俯仰和横滚），不含绕重力轴的偏航，渲染结果不体现脚绕纵轴转向的动作。

### 位移

回放页除姿态外，还展示每只脚相对于以当前时刻为中心的一段时间内平均位置的位移。位移的定义、窗口长度、姿态来源、坐标系、丢帧处理和不展示位移的时间段见 [0017](adr/0017-position-displacement.md)。

- **计算与展示分离**：`DisplacementCalculator` 是 UI 模块里的纯计算，不依赖视图。进入回放页时，对每只脚的整段采样积分一次，得到与窗口长度无关的中间结果 `Track`；用户切换窗口时只用 `Track` 重新算位移，不重新积分，也不影响姿态渲染。
- **输入**：采样点 `SensorReading`（时刻、加速度 g、角速度 deg/s）、该侧的数据缺口 `DataGap`、该侧的校准参考系。数据缺口把采样切成多段，每段独立估计。没有校准参考系的一侧不计算位移。
- **输出**：每个采样点一个位移，单位米，已换算到渲染世界坐标系（x = -左，y = 上，z = 前）；`nil` 表示该时刻不展示位移。回放时刻按最近邻对应到采样点。
- **展示**：`Pose3DView` 在每只脚的原位置放一个灰色小球，标记平均位置；鞋模型相对标记偏移位移。位移为 `nil` 时模型留在标记处。位移按 1 米对应 3 个场景单位放大，每个方向最多偏离标记 3 个场景单位，避免长窗口下模型飞出画面。
- **姿态来源**：位移用陀螺积分加加速度计修正的姿态，姿态渲染只用加速度计的倾斜，回放里同时存在两套。

### 缓冲区生命周期

设备适配层不保存历史：样本整理出来就交给订阅者，没人订阅时直接丢弃。校准阶段需要的历史由校准流程自己累积：

1. 进入校准阶段时创建校准引擎，每个传感器一个缓冲区，从此累积该传感器的全部样本。
2. 校准期间累积量有上限：四步、每步时限 10 秒，至多约 40 秒，50Hz 下每个传感器约 2000 条，内存可以忽略。
3. 校准结束时取消订阅并丢弃累积的样本。录制阶段不使用这份数据（录制走独立的落盘路径）。
4. 累积的样本不是任何 session 的正式数据来源；落盘到 `Calibrations/` 的是交给判定的窗口副本，不是累积样本的完整内容。

## 关键接口

- 设备适配层的接口（`DeviceAdapter`、`DeviceSample`、能力协议、工厂、注册表、设备管理器）见[接口参考](reference/att-sensor-kit-protocol.md)。
- 落盘文件的目录与字段见[数据格式参考](reference/session-data-format.md)。
- 位移计算（`DisplacementCalculator`）：
  - `track(readings:gaps:frame:) -> Track`：积分整段数据，结果与窗口长度无关。
  - `displacements(track:window:) -> [SIMD3<Float>?]`：按窗口长度（秒）算出每个采样点的位移。
  - `index(at:in:) -> Int?`：回放时刻对应的采样下标。

## 数据

### 落盘方式

- 录制数据按数据流拆成多个 JSON Lines 文件，每条记录到达即编码为一行并追加，应用层不做批量缓冲。每路数据流各持有一个文件句柄。
- `left.jsonl`/`right.jsonl` 只为本次实际使用的传感器创建，`gps.jsonl`/`battery.jsonl` 始终生成。`meta.json` 记录传感器数量和实际生成的数据文件名列表，供读取时判断包含哪些数据流。
- 追加写入只保证数据进入 OS 页缓存。真正的持久化由每 10 秒一次的 fsync 兜底：崩溃或被系统杀掉时，每路数据流最坏丢失约 10 秒的数据，而不是整个 session。
- 磁场只为留档，不参与任何计算：校准只用加速度和角速度，回放的姿态渲染只用加速度计，位移计算用加速度和角速度。具备磁场能力的设备由录制会话按固定间隔轮询，落盘为独立的 `magnetic` 记录。

### 校准数据

校准数据是独立于 session 存储的一条落盘路径，由校准记录器负责，写到与 `Sessions/` 平级的 `Calibrations/` 目录。每次进入校准阶段一个目录，目录名（校准 id）随后写进 session 的 `meta.json`。每次尝试（含失败）都保留。写入失败不阻断校准流程；单次体积在百 KB 量级，不做自动清理，用户可从"文件"App 手动删除。

### 数据导出

App 的 Documents 目录（`Sessions/`、`Calibrations/` 所在的目录）对用户可见：可以在设备本地的"文件"App（"我的 iPhone"分类下）里直接浏览、删除、导出，也能通过 Mac Finder（USB 连接）访问。App 本身不会感知外部的增删改；历史记录列表每次进入都重新读取目录内容、不缓存，所以不会显示已被删除的 session。
